# IDEAS: 개인용 키 금고 앱 (가칭)

작성일: 2026-11-05

## 문제

- 서비스 7개를 운영하면서 키가 계속 늘어난다. 메모장 관리는 한계.
- 진짜 병목은 찾는 시간이 아니라 **잘못된 키가 들어갔는데 키 문제인 줄 모르고 디버깅**하는 것. 하루 1~2회, 시간이 많이 든다.
- 흔한 원인: 테스트/라이브 혼동, 다른 서비스 키, 공백/개행, 잘린 값, pem 줄바꿈, 옛 복사본, 폐기/만료.

## 목표

키, 토큰, pem을 저장해 두고 **빠르게 찾아서 확인하고 복사**한다. CI/CD 연동, 팀 공유, 크로스 플랫폼은 지금 하지 않는다.

## 현재 상태와 결정

- Apple 네이티브 앱(SwiftUI + Keychain)을 만들었지만 **자료구조가 맞지 않아 사용 중단**.
- 스킴은 써 봐야 나온다. 그래서 **웹 프로토타입으로 먼저 스킴을 잡는다**.
- 스택: **Laravel + Filament** (마이그레이션과 UI 변경이 싸다. Nova는 유료).
- 스킴이 굳으면 네이티브 앱의 모델만 갈아 끼운다 (Keychain, Face ID, 복사 처리 뼈대는 재사용).

## 프로토타입 규칙

- 로컬에서만 실행. 외부 배포 금지.
- 값 컬럼은 `encrypted` 캐스트. **`APP_KEY`는 금고 밖에 따로 백업** (잃으면 복구 불가).
- 지문(마지막 4자리) 컬럼을 별도로 저장해 목록에서 복호화 없이 표시.
- DB는 SQLite 파일 하나. `.env`와 DB 파일은 `.gitignore`, 에이전트가 접근하는 저장소 밖에 둔다.
- 백업은 암호화해서 NAS에.
- Filament: `password()` + `revealable()`, 목록은 `copyable()`.

## 스킴에 넣을 후보

- 항목: 이름, 서비스, 프로젝트, 환경(test/live/prod), 값, 지문, 쓰는 곳, 발급일, 메모
- 복사 시 앞뒤 공백/개행 제거. pem은 줄바꿈 보존 모드.
- 이름에 환경 표기 (`STRIPE_SECRET_KEY_LIVE`).
- 네이티브가 안 맞았던 이유를 첫 요구사항으로 기록할 것.
