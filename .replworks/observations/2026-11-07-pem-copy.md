# 2026-11-07 PEM copy observation

## Environment

- Host: macOS (darwin), desktop session.
- Product origin: `http://127.0.0.1:8000`, served by `php artisan serve --host=127.0.0.1 --port=8000`.
- Probe: `probes/2026-11-07-pem-copy/probe.mjs` (Playwright, `channel: "chrome"`, headless, clipboard-read/write granted).
- Seed: one Item `E2E PEM Key` (kind `pem`) in the `Infra` container, value `"  -----BEGIN KEY-----\r\nabc\rdef  \r\n"`, created through `ItemManager::create` and deleted after the run.

## Procedure

1. Start the product with `php artisan serve --host=127.0.0.1 --port=8000`.
2. Seed the pem Item described above.
3. Run `node probes/2026-11-07-pem-copy/probe.mjs`.
4. The probe clicks the row copy control (`EL-005`) of the `E2E PEM Key` row, waits, reads the clipboard with `navigator.clipboard.readText`, and compares it exactly.

## Granted observation

The clipboard received exactly the pem-normalized text through the real product path (row copy control -> `ItemManager::copyText` -> `CopyTextPreparer::prepare($value, 'pem')` -> browser `copy-prepared` event -> `navigator.clipboard.writeText`):

| Written (stored Value) | Clipboard text | Equal |
| --- | --- | --- |
| `"  -----BEGIN KEY-----\r\nabc\rdef  \r\n"` | `"-----BEGIN KEY-----\nabc\ndef\n"` | yes |

Raw result:

```json
{
  "clipboard": "-----BEGIN KEY-----\nabc\ndef\n",

    "419 http://127.0.0.1:8000/livewire-8378b839/update"
```

## Pre-existing finding (out of scope, all copy kinds affected)

The copy confirmation message (`EL-010`) did not appear: after the clipboard write, the page's `Livewire.find(id).call('reportCopyResult', ...)` POST returned `419`. The same `419` reproduces for non-pem rows and for a direct `reportCopyResult` call from the console, while declarative `wire:` requests (search filter, row copy dispatch) return `200`. The component-level path is covered by tests (`reportCopyResult(true)` renders the confirmation). The browser JS-bridge `419` predates the pem change and is recorded here without being fixed.
